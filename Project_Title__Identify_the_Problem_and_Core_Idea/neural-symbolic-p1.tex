\section{Summary}
% =====================================================================
Because a VCU118 was not available for Chipyard, we moved from Chipyard and Gemmini to ESP~\cite{esp}, which integrates NVDLA~\cite{nvdla} alongside an Ariane core~\cite{espnvdla}. A VCU118 will be available later through ESP. The neural accelerator is now NVDLA \emph{nv\_small} (int8); the symbolic accelerator is still SAT-Accel~\cite{sataccel}. The research question, workload, baselines, and ReasonLink mechanisms are unchanged.

For P1, every part of the visual-Sudoku pipeline that does not need the board runs and is checked against a reference, and both baselines run end to end with cycle counters (Table~\ref{tab:status}). The one stand-in is the solver: SAT-Accel cannot run yet, so MiniSat~\cite{minisat} solves SAT-Accel's exact memory image.

\section{What Was Built}
% =====================================================================
\textbf{ESP platform.} A departmental server (RHEL 8.10) already has ESP's toolchain: Vivado 2023.2, ModelSim DE 2023.2, and RISC-V GCC 9.2. ESP is pinned to release 2026.1.0, with its NVDLA software installed.

\textbf{NVDLA classifier.} We use the LeNet~\cite{lenet} that ESP ships for NVDLA. Recompiling it reproduces ESP's loadable byte for byte, which pins down ESP's compiler flags. Our Python int8 emulator reproduces ESP's published NVDLA output exactly and generates the per-cell scores that stand in for NVDLA's output buffer. ESP's weights do not match NVDLA's input preprocessing, so we retrained the same network and compiled it with ESP's flags.

\textbf{Workload.} Sudoku is encoded with 729 variables and 11{,}988 base clauses, and predicted givens are added as unit clauses. We generated 1{,}000 unique-solution puzzles with 24--40 clues each, in the style of visual Sudoku~\cite{satnet}, with MNIST test digits in the given cells.

\textbf{SAT solver.} We ported SAT-Accel's host-side conversion (CNF to device memory image) to C. A golden test compiles SAT-Accel's own parser next to the port and compares every byte. SAT-Accel's emulation needs Vitis \texttt{v++} and XRT, which the server lacks, so a MiniSat backend decodes the image the way the device's copy-in would and solves it. PySAT~\cite{pysat} provides the reference answers.

\textbf{Baselines.} A host thread runs SAT-Accel's native flow: argmax, image build, copy into device buffers, then a doorbell and completion poll. A device thread decodes and solves. Every phase is timed with \texttt{rdtsc} (\texttt{rdcycle} on RISC-V). The double-buffered baseline uses two buffer sets with explicit ownership. We run each baseline \emph{faithful} (all 10.5\,MB of allocated buffers cleared and copied, as SAT-Accel's host does) and \emph{lean} (only the bytes in use).

Table~\ref{tab:baselines} gives the first handoff breakdown, and it supports H1 and H2.
\begin{itemize}
\item \emph{H1.} In SAT-Accel's native flow the handoff is 74\% of end-to-end time (51\% when lean). The argmax that actually consumes the neural output takes under 1\,$\mu$s; the remainder is rebuilding and copying an image of the unchanging base formula: 10.5\,MB migrated per puzzle to deliver 36 givens.
\item \emph{H2.} Double buffering hides the handoff only when it is shorter than the solve. The faithful handoff (2.6\,ms vs.\ a 0.76\,ms solve) stays 70\% exposed. The lean handoff is almost fully hidden but still moves 632\,KB per puzzle.
\end{itemize}
$T_{\text{sync}}$ is below 1\,$\mu$s with busy polling, whereas SAT-Accel's host polls once per second.

\textbf{Limitations and open issues.} These are host x86 times. On ESP, conversion runs on Ariane and transfers use DMA, so the numbers will change; the RISC-V build of the same harness is ready for that. $T_{\text{sat}}$ is MiniSat, not SAT-Accel; running SAT-Accel is the main open issue. NVDLA's outputs are emulated until NVDLA runs on ESP. Sudoku at these clue counts needs almost no search, so testing H3 will need harder instances. Smaller tooling issues (compiler flags, line endings, a missing \texttt{zlib.h} on the server) are resolved and logged in \texttt{PROGRESS.md}.

\section{Reproduction Steps}
\label{app:steps}
Every step taken for P1. Commands run from the repository root. Parts A and C need a machine with the ESP platform (our server); part B runs on any Linux or WSL machine.

\smallskip\noindent\emph{A. ESP server, one-time setup:} inventory; ESP pinned with only the NVDLA software; this repository (the server receives code through git, so run \texttt{git pull} before each server step).
{\scriptsize
\begin{verbatim}
bash env/server_probe.sh
git clone https://github.com/sld-columbia/esp.git ~/esp
cd ~/esp && git checkout 2026.1.0
git submodule update --init \
    accelerators/third-party/NV_NVDLA/sw
git clone https://github.com/AaronCherian404/\
ReasonLink.git ~/ReasonLink
cd ~/ReasonLink
git submodule update --init third_party/minisat
\end{verbatim}
}

\noindent\emph{B. Local:} environment; classifier and workload; SAT-Accel image and solver checks; baselines.
{\scriptsize
\begin{verbatim}
bash env/setup_wsl.sh
source ~/venvs/reasonlink/bin/activate
bash workload/fetch_esp_lenet.sh
python workload/nvdla_lenet.py --model esp --check
python workload/train_lenet.py
python workload/dataset.py --num 1000 --seed 0
python workload/reference_solve.py
(cd handoff && make && make golden && make solvecheck)
(cd baselines && make run)
\end{verbatim}
}

\noindent\emph{C. ESP server, builds.} The script recompiles ESP's demo network and checks it against ESP's shipped loadable (md5 \texttt{9831533f}). It then compiles ours to \texttt{build/nvdla/rl\_lenet.nvdla} (md5 \texttt{eb4c0813}). \texttt{make riscv} builds the static RISC-V baselines.
{\scriptsize
\begin{verbatim}
ESP_ROOT=~/esp bash workload/nvdla_compile.sh
(cd baselines && make riscv)
\end{verbatim}
}
\noindent The script's compiler call is equivalent to:
{\scriptsize
\begin{verbatim}
NVC=~/esp/accelerators/third-party/NV_NVDLA/\
sw/prebuilt/x86-ubuntu
LD_LIBRARY_PATH=$NVC $NVC/nvdla_compiler \
  --prototxt lenet_mnist.prototxt \
  --caffemodel rl_lenet.caffemodel \
  --calibtable rl_lenet.json \
  --cprecision int8 --configtarget nv_small \
  --quantizationMode per-filter --informat nchw
\end{verbatim}
}
\noindent Only per-filter quantization with \texttt{nchw} input reproduces ESP's loadable; we tried per-kernel with each input format and per-filter with \texttt{nchw} and \texttt{nhwc}. Inputs are passed by bare file name, because \texttt{-{}-calibtable} fails with an absolute path. For the RISC-V build, \texttt{make riscv} supplies a declarations-only \texttt{zlib.h}, which MiniSat's headers include but the server's toolchain lacks.
